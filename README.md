# 과제 10: 정렬 알고리즘의 성능 및 안정성 비교

선택 정렬, 버블 정렬(일반 / 조기 종료), 삽입 정렬(`>` / `>=`)을 구현하고, 비교 횟수·데이터 이동 횟수·안정성을 측정하여 분석한 보고서입니다.

- 소스 코드: `sort_compare.c`
- 컴파일: `gcc -O2 -Wall -Wextra -o sort_compare sort_compare.c`
- 실행: `./sort_compare` (약 40초 소요)
- 난수 생성기(xorshift64\*)를 직접 구현하고 시드를 `20250101`로 고정했습니다. 따라서 Windows/macOS/Linux 어디에서 실행해도 이 README의 수치와 동일한 결과가 나옵니다(`rand()`는 운영체제마다 구현이 달라 사용하지 않았습니다).

---

## 1. 실험 방법

### 1.1 데이터와 측정 기준

- 데이터 1개는 `(Key1, Key2, originalIndex)`로 구성됩니다. `Key1`과 `Key2`는 각각 0~1,000,000 범위에서 생성한 난수이며, 정렬은 `Key1`을 기준으로 수행합니다. `originalIndex`는 입력 순서를 기록하여 안정성을 검증하는 데 사용합니다. 두 키는 하나의 구조체로 함께 이동합니다.
- 데이터 개수는 모든 실험에서 10,000개입니다.
- 운영체제와 무관하게 0~1,000,000 전체 범위가 동일하게 생성되도록 직접 구현한 64비트 난수 생성기를 사용했습니다.
- **비교 횟수**: 정렬 순서를 결정하기 위해 Key1끼리 비교한 횟수(반복문 조건 검사는 제외).
- **이동 횟수**: 데이터 구조체 전체를 복사·대입한 횟수. 교환(swap)은 3회, 삽입 정렬은 임시 변수 저장 1회 + 한 칸 이동 1회씩 + 최종 위치 대입 1회로 계산했습니다.
- 원본 배열 복사, 데이터 생성, 사전 정렬(`qsort`)은 비교/이동 횟수에 포함하지 않았습니다.
- 정렬 결과는 매번 `isValidResult()`로 검증했습니다(Key1 오름차순 + 체크섬으로 데이터 유실·변형이 없는지 확인).

### 1.2 구현한 정렬

| 정렬                  | 구현 요점                                                                                     |
| --------------------- | --------------------------------------------------------------------------------------------- |
| 선택 정렬             | 정렬되지 않은 구간에서 최솟값을 찾아 현재 위치와 교환 (`minIndex != i`일 때만 교환, 3회 이동) |
| 버블 정렬             | 인접한 두 데이터를 `>`로 비교해 교환. 일반 버전은 모든 순회를 수행                            |
| 버블 정렬 (조기 종료) | 한 번의 순회에서 교환이 한 번도 없으면 종료. 그 외 구현은 일반 버전과 동일                    |
| 삽입 정렬 (Case A)    | 이동 조건 `data[j].key1 > current.key1`                                                       |
| 삽입 정렬 (Case B)    | 이동 조건 `data[j].key1 >= current.key1`                                                      |

다섯 가지 정렬 구현은 각 실험에서 동일한 원본 데이터의 복사본을 입력으로 받습니다.

## 2. 무작위 데이터 100회 실험 결과

매 시행마다 새 무작위 데이터 10,000개를 한 번 생성한 뒤, 동일한 복사본을 각 정렬에 제공했습니다. 100회 모두 정렬 결과가 올바른 것을 확인했습니다(`All Trials Correct : Yes`).

| 정렬                  |  총 비교 횟수 | 평균 비교 횟수 | 평균 이동 횟수 |
| --------------------- | ------------: | -------------: | -------------: |
| 선택 정렬             | 4,999,500,000 |  49,995,000.00 |      29,971.95 |
| 버블 정렬             | 4,999,500,000 |  49,995,000.00 |  74,993,608.44 |
| 버블 정렬 (조기 종료) | 4,998,594,095 |  49,985,940.95 |  74,993,608.44 |
| 삽입 정렬             | 2,500,785,965 |  25,007,859.65 |  25,017,867.48 |

### 일반 버블 정렬 vs 조기 종료 버블 정렬 (무작위 데이터)

- 총 비교 횟수 차이: 4,999,500,000 − 4,998,594,095 = **905,905회**, 평균 약 **9,059회**로 전체의 약 **0.02%** 입니다.
- 이동 횟수는 두 방식이 완전히 같습니다. 조기 종료는 "불필요한 순회"만 줄일 뿐 교환 횟수에는 영향이 없기 때문입니다.

## 3. 입력 상태별 성능 비교

### 3.1 부분 정렬 데이터 생성 방법

1. 무작위 데이터 10,000개를 한 번 생성한 원본(base)으로 삼습니다.
2. 이 원본을 Key1 기준으로 정렬하여 **Sorted Data**를 만듭니다(`qsort`, Key1이 같으면 원래 순서 유지. 사전 준비 작업이므로 횟수에 포함하지 않음).
3. Sorted Data를 뒤집어 **Reverse-Sorted Data**를 만듭니다.
4. Sorted Data에서 서로 다른 두 위치를 무작위로 골라 교환하는 작업을 **n/20 = 500회** 수행하여 **Partially Sorted Data**를 만듭니다.

즉 세 입력은 모두 같은 원본에서 파생되었습니다. 부분 정렬 데이터는 최대 1,000개(10%)가 제자리에서 벗어날 수 있는 설계이며, 실제 측정 결과 **10,000개 중 960개(9.60%)** 의 위치만 완전 정렬 상태와 달라졌습니다. 즉 약 90.4%는 제자리에 있고 나머지는 흐트러진 상태입니다. 각 입력에서 `originalIndex`는 입력 순서대로 다시 부여했습니다.

**인공지능 활용 내용**: 부분 정렬 데이터를 만드는 방법을 AI(Claude)에게 문의하여 "정렬된 데이터에서 일부 원소를 무작위로 교환", "일정 구간만 섞기", "소수의 무작위 교란" 등의 후보를 조사했습니다. 그중 정렬 정도를 `교환 횟수`라는 하나의 매개변수로 조절할 수 있고 재현하기 쉬운 첫 번째 방법을 선택했습니다. 교환 횟수는 n/20(500회)로 정했고, 실제로 얼마나 흐트러졌는지는 직접 측정(960개, 9.60%)하여 확인했습니다.

## 4. 안정성 검증

### 4.1 검증 방법

정렬 전 각 데이터의 입력 순서를 `originalIndex`에 저장해 두고, 정렬 후 **Key1이 같은 인접한 두 데이터의 `originalIndex`가 오름차순인지** 검사했습니다(`stabilityViolations()`). 순서가 뒤바뀐 쌍의 개수가 0이면 안정, 1 이상이면 불안정입니다. 정렬 결과가 올바르게 오름차순인지, 체크섬이 보존되었는지도 함께 확인했습니다.

### 4.2 사용한 입력 데이터

무작위 10,000개 데이터는 Key1 중복이 거의 없어(약 50쌍) 검증에 충분하지 않으므로 별도의 시험 데이터를 사용했습니다.

- **시험 1 (과제 예시)**: `(527,100) (527,200) (125,300) (892,400)` — Key1이 527인 데이터가 2개.
- **시험 2 (중복 다수)**: Key1을 0~9 범위에서 뽑은 데이터 1,000개. 같은 Key1을 가진 데이터가 평균 약 100개씩 존재합니다.

### 4.3 결과

시험 1의 정렬 결과(Key1이 같은 두 데이터의 순서에 주목):

| 정렬                       | 결과                                        | 순서 뒤바뀜 |
| -------------------------- | ------------------------------------------- | ----------: |
| 원본                       | (527,100) (527,200) (125,300) (892,400)     |           - |
| 선택 정렬                  | (125,300) **(527,200) (527,100)** (892,400) |           1 |
| 버블 정렬 (일반/조기 종료) | (125,300) **(527,100) (527,200)** (892,400) |           0 |
| 삽입 정렬 (`>`)            | (125,300) **(527,100) (527,200)** (892,400) |           0 |
| 삽입 정렬 (`>=`)           | (125,300) **(527,200) (527,100)** (892,400) |           1 |

| --------------------- | --------: | ------------ | ------: | ------: |
| 선택 정렬             |       297 | **Unstable** | 499,500 |   2,631 |


### 4.4 원인 설명

- **선택 정렬 (불안정)**: 최솟값을 현재 위치와 **멀리 떨어진 곳에서 교환**하기 때문입니다. 시험 1에서 `(125,300)`을 맨 앞으로 보내려고 0번 위치의 `(527,100)`과 교환하면, `(527,100)`이 뒤쪽으로 점프하여 `(527,200)` 뒤에 놓입니다. 교환 한 번이 사이에 있는 같은 키 데이터를 건너뛰어 버리므로 상대 순서가 깨집니다.
- **버블 정렬 (안정)**: `>`일 때만 **인접한** 두 데이터를 교환합니다. 키가 같으면 교환하지 않으므로 같은 키끼리 서로를 지나칠 일이 없습니다. 조기 종료 여부는 교환 규칙을 바꾸지 않으므로 안정성에 영향이 없습니다.
- **삽입 정렬 `>` (안정)**: 앞 데이터의 키가 **엄격히 클 때만** 한 칸 밀어냅니다. 키가 같으면 이동을 멈추고 그 바로 뒤에 삽입하므로, 나중에 들어온 같은 키 데이터가 항상 뒤에 놓입니다.
- **삽입 정렬 `>=` (불안정)**: 키가 같은 앞 데이터까지 밀어내고 그 **앞에** 삽입합니다. 그래서 같은 키를 가진 데이터 그룹의 순서가 통째로 뒤집힙니다. 시험 2에서 Key1이 0~9인 10개 그룹이 각각 뒤집혀 1,000 − 10 = 990쌍이 뒤바뀐 것이 이를 보여줍니다.

### 4.5 삽입 정렬에서 `>`와 `>=`의 차이

- **안정성**: `>`는 안정, `>=`는 불안정입니다(위 결과).
- **이동 여부**: 같은 키 데이터에 대해 `>`는 이동하지 않고 멈추지만, `>=`는 한 칸씩 계속 이동합니다.
- **성능**: `>=`는 같은 키를 만날 때마다 추가 비교와 이동이 발생하여 시험 2에서 비교 224,748 → 274,594, 이동 225,749 → 275,686으로 늘었습니다. 즉 `>=`는 불안정할 뿐만 아니라 중복 키가 많을수록 더 느립니다. 키가 모두 다른 경우(Sorted/Reverse 입력 등 중복이 거의 없는 입력)에는 두 연산자의 차이가 거의 나타나지 않습니다.

## 5. 분석

### 5.1 비교 횟수와 이동 횟수의 이론적 근거

- **선택 정렬**은 입력과 관계없이 항상 `n(n−1)/2 = 49,995,000`회 비교합니다(최솟값을 찾으려면 남은 구간을 끝까지 봐야 하기 때문). 이동은 교환이 일어난 횟수의 3배입니다.
- **버블 정렬(일반)** 역시 순회를 모두 수행하므로 비교 횟수가 항상 49,995,000회입니다. 이동 횟수는 `3 × (역전 쌍의 수)`입니다. 인접 교환은 정확히 역전 쌍 1개를 없애기 때문입니다.
- 삽입 정렬의 이동 횟수는 본 프로그램의 측정 기준에 따라 `2(n−1) + 역전 쌍의 수`로 계산됩니다. 각 원소를 임시 변수에 저장하고 최종 위치에 대입하는 횟수에, 앞 원소를 한 칸씩 이동하는 횟수를 더한 값입니다.
  실험값과 일치하는지 확인했습니다.

| 입력         | 역전 쌍 수 (삽입 이동 − 19,998) | 버블 이동 ÷ 3 |
| ------------ | ------------------------------: | ------------: |
| 역순         |                      49,994,947 |    49,994,947 |
| 부분 정렬    |                       3,121,138 |     3,121,138 |
| 무작위(평균) |                   약 24,997,869 | 약 24,997,869 |

무작위 입력의 역전 쌍 수는 이론 기댓값 `n(n−1)/4 ≈ 24,997,500`에 가깝습니다. 역순에서 역전 쌍이 `n(n−1)/2 = 49,995,000`보다 53개 적은 것은 Key1이 같은 쌍(중복 키)은 역전이 아니기 때문입니다.

### 5.2 입력 정렬 상태의 영향

- **이미 정렬된 데이터**: 삽입 정렬은 한 번씩만 비교하면 되어 비교 9,999회, 이동 19,998회(임시 저장 + 최종 대입만 발생)로 가장 빠릅니다. 조기 종료 버블 정렬도 첫 순회에서 교환이 없어 바로 끝나므로 비교 9,999회, 이동 0회입니다. 반면 일반 버블 정렬과 선택 정렬은 입력과 무관하게 49,995,000회를 비교합니다. 선택 정렬은 이미 제자리이므로 교환이 없어 이동 0회입니다.
- **역순 데이터**: 최악의 경우입니다. 모든 정렬의 비교 횟수가 49,995,000회 수준이 됩니다(조기 종료도 매 순회 교환이 일어나 이점이 없음). 이동 횟수는 버블 정렬이 약 1.5억 회로 가장 많고, 삽입 정렬이 약 5,000만 회, 선택 정렬은 교환을 약 5,028번(15,084 ÷ 3)만 하므로 15,084회로 가장 적습니다.
- **부분 정렬 데이터**: 약 9.5%만 흐트러져 있어 역전 쌍이 약 312만 개뿐이므로, 삽입 정렬은 비교 약 313만 회, 이동 약 314만 회로 무작위 대비 약 8분의 1 수준입니다. 선택 정렬의 비교 횟수는 변하지 않고(49,995,000), 이동은 1,509회로 매우 적습니다. 버블 정렬의 이동은 약 936만 회입니다.

### 5.3 조기 종료 조건의 효과

- **정렬된 데이터**: 비교 횟수 49,995,000 → 9,999회로 **약 5,000분의 1** 로 줄어듭니다. 가장 큰 효과를 보이는 경우입니다.
- **무작위 데이터**: 감소량은 평균 9,059회(약 0.02%)에 불과합니다. 무작위 데이터에서는 가장 작은 값이 맨 뒤에 있을 가능성이 높아, 버블 정렬이 작은 값을 한 순회에 한 칸씩만 앞으로 옮기므로 거의 마지막 순회까지 가야 정렬이 끝나기 때문입니다.
- **역순 데이터**: 효과 없음(매 순회마다 교환 발생).
- **부분 정렬 데이터**: 49,995,000 → 49,895,765회로 약 0.2%(99,235회)만 감소합니다. 일부 원소만 흐트러져 있어도, 오른쪽 끝에 있던 작은 값이 한 순회에 한 칸씩만 이동하므로 총 9,554번의 순회가 필요했기 때문입니다(전체는 9,999번). 조기 종료는 "정렬이 끝난 뒤의 낭비"만 막아 줄 뿐, 한 순회에 한 칸씩만 이동하는 버블 정렬의 구조적 한계를 해결하지는 못합니다.

### 5.4 알고리즘별 성능 차이의 원인

- 세 알고리즘 모두 최악·평균에서 `O(n²)`이지만 입력에 대한 **적응성**이 다릅니다. 삽입 정렬은 역전 쌍 수에 비례하여 일하므로 정렬에 가까울수록 급격히 빨라지고(최선 `O(n)`), 선택 정렬은 입력과 관계없이 비교 횟수가 항상 같습니다. 버블 정렬은 조기 종료를 넣어야 정렬된 입력에서만 `O(n)`에 가까워집니다.
- **이동 횟수** 측면에서는 선택 정렬이 최대 `3(n−1)`회로 상한이 있어 이동 비용이 큰 데이터에 유리합니다. 무작위 데이터 기준 선택 정렬은 평균 약 3만 회인 반면 버블 정렬은 약 7,499만 회, 삽입 정렬은 약 2,502만 회입니다. 선택 정렬은 한 번의 교환으로 데이터를 최종 위치로 직행시키지만, 그 대가로 안정성을 잃습니다.
- 버블 정렬은 인접한 데이터를 교환하는 방식이라 역전 쌍 하나를 해결하는 데 항상 교환(이동 3회)이 필요합니다. 삽입 정렬은 역전 쌍 하나당 1회 이동만 필요하여 같은 일을 약 3분의 1의 이동 비용으로 처리합니다. 그래서 무작위 데이터에서 삽입 정렬은 버블 정렬보다 비교 횟수가 약 절반, 이동 횟수가 약 3분의 1입니다.

### 5.5 정리

| 관점      | 선택                    | 버블                   | 버블(조기 종료)             | 삽입                          |
| --------- | ----------------------- | ---------------------- | --------------------------- | ----------------------------- |
| 비교 횟수 | 입력과 무관, 항상 최대  | 입력과 무관, 항상 최대 | 정렬된 입력에서만 크게 감소 | 입력이 정렬에 가까울수록 급감 |
| 이동 횟수 | 가장 적음 (최대 3(n−1)) | 가장 많음              | 가장 많음                   | 중간 (역전 쌍 수에 비례)      |
| 안정성    | 불안정                  | 안정                   | 안정                        | `>`: 안정 / `>=`: 불안정      |

결론적으로 입력이 이미 정렬되어 있거나 일부만 흐트러져 있는 경우에는 삽입 정렬이 가장 유리하고, 조기 종료 조건과 삽입 정렬의 비교 연산자(`>`)를 올바르게 선택하는 것이 성능과 안정성 모두에 중요하다는 것을 실험으로 확인했습니다.
